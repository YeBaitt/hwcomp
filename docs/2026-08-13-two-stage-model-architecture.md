# 两阶段模型通俗讲解：Stage-1 NAFNet + Stage-2 SD2.1 扩散

**本文写给谁**：这篇文章是写给**完全零基础**的读者的。你不需要学过编程，不需要听说过"机器学习""深度学习"，甚至忘了"像素"是什么也没关系。你只需要一样东西：**耐心**。全文会像一位耐心的老师讲课一样，把每个专业词都用大白话加生活比喻解释一遍，第一次出现的地方讲透，之后就用比喻当"快捷键"反复使用。读完你会明白：我们的照片修复系统其实是"一家有两间车间的工厂"，车间一负责把照片洗净捋直，车间二请一位"很懂好照片长什么样"的画师精修，最后两个车间配合，输出一张又干净又自然的好照片。

## 0. 先建立直觉：一家"照片修复工厂"的两个车间

想象你手里有一张**模糊、有噪点、颜色发闷**的旧照片（我们叫它 **LQ**，Low Quality，低质量图）。你想把它变成一张**清晰、干净、边缘锐利、看起来很自然**的好照片（我们尽量靠近一个"标准答案" **GT**，Ground Truth，正确答案/真实原图）。这个"把脏照片变好"的过程，就叫**图像增强/修复**（把图片变得更好看更清楚）。

我们搭了一家有两间车间的小工厂来处理这件事：

- **车间一（Stage-1 NAFNet）＝ 基础清理**：先把照片"洗净、捋直"。去噪点、去模糊、恢复基本的轮廓和颜色。它干的是"糙活"，但特别稳——它修完之后，照片已经七七八八干净了，而且非常"忠实原图"（不会乱改内容）。
- **车间二（Stage-2 SD2.1 扩散）＝ 精装修**（先剧透一句：**扩散**是一种"从一团纯噪声里一步步雕出清晰图"的技术，具体在第 3 节细讲）：请一位非常懂"好照片长什么样"的画师来精修。这位画师负责补细节、补纹理，让边缘变得自然，让照片看起来"像真的"，而不是像被软件抹过一遍。它干的是"巧活"，擅长制造"自然感"。
- **为什么要拆成两个车间，不一个车间干完？** 因为这两件事各有各的强项，也各有各的短板：
  - 车间一**保真**：结果跟原图长得像、数值对得上（我们叫"保真"，fidelity）。短板是它只能"清洗"，很难"无中生有"地造出原本丢失的细节，容易显得"软""糊""假平滑"。
  - 车间二**感知**：结果"看起来自然、真实、像好照片"（我们叫"感知"，perception）。短板是它天生爱自由发挥，如果没人管着，它可能把原图改成"另一张好看的图"，跟原图对不上。

所以我们的设计是：**车间一打底保真，车间二精修补感知，最后用一个"旋钮"来调节谁的声音更大**。两个车间合在一起，互相补足，这就是整篇文章要讲的核心。设计文档里给这两个车间起了正式的名字：车间一叫"**保真打底**"（fidelity base），车间二叫"**生成主干**"（generation backbone）——记住这对名字，后面会反复用到。

再交代一下我们的"家底"：手上一共有 **78 对**（脏照片，标准答案）图片对，这就是我们教模型用的全部"教材"。教材不多，所以设计上格外小心：用别人预训练好的权重起步（站在巨人肩膀上）、把大图切成小块反复学、以及后面要讲的轻量微调，全都是为了让"少少的教材"也能教会模型。比赛的真实评分是多项"像不像"（有参考指标）和"自不自然"（无参考指标）的加权平均，而官方具体用哪几项、权重多少，要等决赛入围名单（约 9~20 名）公布才知道——所以我们特意留了四个"旋钮"，到时候按官方标准再拧一拧就行。

## 1. 一张图在计算机里到底是什么（把地基打好）

### 1.1 像素、通道、分辨率

- **像素（pixel）**：一张数码照片，放大到极致，会看到密密麻麻的小方格，每个小方格就是一个"像素"，是照片的最小单位。你可以把像素想象成**马赛克的一块小砖**，整张照片就是由千千万万块小砖拼出来的。
- **RGB 三通道**：每一块"小砖"其实不是一个数字，而是**三个数字**：红的程度（R，Red）、绿的程度（G，Green）、蓝的程度（B，Blue）。把三种颜色的亮度按不同比例混合，就能配出任何颜色——就像调颜料，红+绿+蓝三罐颜料随便调。所以一张彩色图在电脑里，实际上是**三张叠在一起的"灰度表格"**，每个格子存一个 0~255 的亮度数字。
- **分辨率（resolution）**：指照片"长多少像素 × 宽多少像素"。比如 **4K** 图，就是横向约 4000 个像素、纵向约 3000 个像素（不同 4K 规格略有差异），一共约一千万个像素点。一千万个像素 × 每个像素 3 个数字，等于**几千万个数字**。

> **一句话记住**：一张图在电脑里 = 一个由几千万个数字组成的大表格。表格里的数字是"颜色深浅"，位置是"横竖坐标"。

下面是一张 2×2 的迷你图（宽 2 个像素、高 2 个像素）在电脑里真实的样子，每个格子 `[R, G, B]` 是一个像素的三个颜色数字：

```
   ┌─────────────────┬─────────────────┐
   │ [200, 30, 20]   │ [210, 25, 15]   │   ← 这一行两个像素都是红色系（R 大）
   ├─────────────────┼─────────────────┤
   │ [190, 35, 25]   │ [205, 28, 18]   │   ← 这一行也是红色系，只是稍微暗一点
   └─────────────────┴─────────────────┘
```

真实照片只是把这个表格扩大成几千万格而已。所以"修图"这件事，翻译成电脑的话就是：**把这个大表格里的数字改得更合理**——该亮的亮、该干净的去噪点、该锐利的变锐利，改完再把数字翻译回图片。

### 1.2 LQ / GT / HR 三个缩写

- **LQ（Low Quality，低质量图）**：我们手里的"脏照片"，也就是输入。可能模糊、有噪点、压缩失真。
- **GT（Ground Truth，真实答案）**：这张照片"原本应该长什么样"的标准答案。训练模型时，我们把 GT 当作"老师手里的标准答案"用来打分。它一般由专业设备拍出来或者人工精修得到。
- **HR（High Resolution，高分辨率图）**：指清晰的大图。在"超分辨率"任务里 HR 通常是目标；但我们的系统是**同分辨率修复**（不放大），所以 HR/LQ 主要是"高清/低清"的相对说法。我们项目里 GT 就是那对图片里以 `_gt.png` 结尾的"标准答案"文件。

配对的照片在文件夹里长这样（这是代码里真实的配对规则）：

```
   20170613_133128_ARC.png        ← 脏照片（LQ，题目）
   20170613_133128_ARC_gt.png     ← 标准答案（GT，答案）
   20170613_133129_ARC.png
   20170613_133129_ARC_gt.png
   ...（共 78 对，真实文件名都以 _ARC 结尾）
```

规则一句话：除了以 `_gt.png` 结尾的文件，其余每张 `.png` 都去找它同名的 `_gt.png` 兄弟当标准答案。

### 1.3 "修复网络"到底在干什么

所谓"增强/修复"的**神经网络**（可以理解为：一台能学习、能记住规律的超级计算器）干的事其实特别朴素：

> 输入几千万个数字（脏照片）→ 经过一层层"加工流水线" → 输出另一组几千万个数字（修好的照片），并且让输出的照片**尽量接近标准答案 GT**。

它不会"凭空发明"修复公式，而是**从大量的"脏照片 + 标准答案"成对例子中自己总结规律**：看到什么程度的脏，就该补到什么程度。这跟我们学做题一样——看多了"例题和答案"，慢慢就会自己解题了。

这里顺便分清两个阶段，后面会反复出现：

- **训练（training）** = "学习阶段"：模型一边看例题一边改自己，需要标准答案 GT 来打分、来纠正。我们项目里 `train_stage1.py` 这种脚本干的就是这件事。
- **推理（inference）** = "上工阶段"：模型已经学完，拿到一张新照片直接输出结果，不再需要答案，也没人给它打分。比赛时批量处理真实照片，走的就是推理。

车间一和车间二都要经历这两步：先训练（或用现成权重），再推理。

## 2. Stage-1：NAFNet（车间一）

### 2.1 一句话介绍 + 比喻

> **NAFNet**（全称来自论文 "Simple Baselines for Image Restoration"，一个"简单的图像修复基线模型"，作者 Chen Liangyu 等，2022 年发表）是一个"**图进图出**"的神经网络，专门用来做图像修复：把一张脏照片"过一遍"就变干净。

**比喻**：把 NAFNet 想象成一家高档洗衣店的**自动洗护机**。脏照片从一端进去，经过机器内部一层层的"清洗滚筒"，从另一端出来时已经去污、去皱、整理好了。它干活稳定、老实，不会自作主张给照片"加戏"，所以特别适合当"保真打底"。

我们用的是开源项目里的 NAFNet（从 megvii-model 这个 GitHub 仓库来的，代码放在我们项目的 `vendor/NAFNet/` 目录下，通过 `sys.path.insert` 注入路径后导入）。这里"vendor"（供应商目录）的意思是：把别人写好的代码**原样拷贝一份到自己的项目里**，避免依赖网络、保证版本固定——就像把超市里买的标准零件囤在自己仓库里，随时取用。

### 2.2 结构长什么样（漏斗/U 形比喻 + ASCII 图）

NAFNet 的内部结构是一个经典的**编码器（Encoder）— 中间块（Middle）— 解码器（Decoder）** 结构，形状像一个**漏斗**（先收窄、再放回原宽），也像字母 **U**：

- **编码器（Encoder，可以理解为"压榨/提炼区"）**：一层层把图片**缩小**（每缩一层，横向纵向各减一半）。同时每一层都把图"看得更抽象"——一开始看的是具体像素，慢慢看出边缘、纹理、物体轮廓。就像读一篇文章：先看单个字，再看句子、段落，最后抓住主旨。缩小的过程也是在**压缩信息、提取"更高级的要点"**。
- **中间块（Middle，可以理解为"思考区"）**：在图片被压缩到最小、最"浓缩"的地方，放一串"处理块"慢慢琢磨——相当于把全文的提纲拿到手，认真想"这照片哪儿脏、该修哪儿、该修到什么程度"。
- **解码器（Decoder，可以理解为"扩写/还原区"）**：一层层把图片**放大回原始尺寸**，把思考的成果还原成一张完整的图。就像拿着改好的提纲，重新扩写回一篇文章。
- 最后，NAFNet 还有一个"**全局残差**（global residual）"：把最初的输入图**原样加回来**一次。这招的意思是"我只负责补齐你缺的部分，不把你整个重画"——就像洗衣店只洗去污渍，不会把你的衣服换成另一件。这个设计让模型学习起来容易得多。

下面这个 ASCII 漏斗图，从左到右看，能直观看到图片尺寸怎么变小又变大（`W×H` 是宽×高，数字只是示意，表示逐层减半又逐层翻倍）：

```
          输入 W×H（脏照片）
                │
                ▼
   ┌───────────────────────────────┐
   │ 开头小卷积：把 3 通道 → 64 通道   │  （正式开工前先登记；卷积＝一个小方窗
   └───────────────────────────────┘   在图上滑动、逐格提取局部信息）
                │
                ▼
     编码器 Encoder（图越缩越小，看的东西越来越抽象）
   ┌─────────────────────────────────────┐
   │  [块×2]  →  缩小一半  →  W/2 × H/2   │
   │  [块×2]  →  缩小一半  →  W/4 × H/4   │
   │  [块×4]  →  缩小一半  →  W/8 × H/8   │
   │  [块×8]  →  缩小一半  →  W/16 × H/16 │   ← 图最小、最浓缩
   └─────────────────────────────────────┘
                │
                ▼
       中间块 Middle（浓缩处想清楚）
   ┌───────────────────────────────┐
   │   [块×12] 反复处理最浓缩的图     │
   └───────────────────────────────┘
                │
                ▼
     解码器 Decoder（图越放越大，把结果还原成图）
   ┌─────────────────────────────────────┐
   │  放大 2 倍  →  [块×2]  ← 把对应层结果加回来 │
   │  放大 2 倍  →  [块×2]  ← 把对应层结果加回来 │
   │  放大 2 倍  →  [块×2]  ← 把对应层结果加回来 │
   │  放大 2 倍  →  [块×2]  ← 把对应层结果加回来 │
   └─────────────────────────────────────┘
                │
                ▼
     结尾小卷积：变回 3 通道（还原成彩色图）
                │
                ▼
    + 全局残差（加上原始输入）→ 输出干净图
```

**"通道数 width=64"是什么意思？** 每一层的图片都有多个"小本子"同时记账，通道（channel）数就是本子的数量，width=64 表示这一层**同时用 64 个小本子**，每个本子记一种不同的信息（比如：本子 A 记水平边缘，本子 B 记垂直边缘，本子 C 记颜色分布……）。通道越多，这一层能记的信息种类越多。图中每一步的"块×N"，N 就是该层放多少个"处理块（NAFBlock）"——可以理解为这条流水线上装了几个工位，工位越多这一层越"下功夫"。

> 顺便说：NAFNet 里用的基本工位叫 **NAFBlock**。NAF 的全称是 "Nonlinear Activation Free"（无非线性激活函数），它的"门控"（gate，可以理解成水流开关）非常朴素：把信息流平均分成两股 `x1`、`x2`，然后直接**相乘** `x1 × x2`，中间不装任何"非线性激活"（一种常见的让模型变聪明的小机关）。就是这份"朴素到极致"的设计，让它又好又快——很多花哨的机关其实都可以省掉。

这个 `x1 × x2` 的门控在代码里有个名字叫 **SimpleGate**，原文就几行：把通道从中间一分为二，再逐位置相乘（`x1, x2 = x.chunk(2, dim=1); return x1 * x2`）。为什么"直接相乘"就够了？因为相乘天然是一种"两股信号互相决定开关"的机制：两股都强，结果才强；一股弱，结果就跟着弱。这正好起到了"自动筛选重要信息"的作用，却完全不需要额外的激活函数。这份简洁正是 NAFNet 名字的由来，也是它又准又快的底气——正如论文标题所说，它只是"图像修复的一个简单基线"。

### 2.3 逐条讲清楚 config 参数（一条都不能漏）

下面的表格把我们给 Stage-1 配的每一项参数（来自 `config.yaml` 和代码里的默认值）都列出来，用大白话解释。这是很多读者最想要的部分，请对照着看。

| 参数（代码里的名字） | 我们用的值 | 大白话解释 |
|---|---|---|
| `img_channel=3` | 3 | 输入是 RGB **三通道**彩色图（红、绿、蓝三张叠起来的表格），所以入口是 3 条道。 |
| `width=64` | 64 | 每一层同时用 **64 个"小本子"** 记账，即 64 个通道，代表该层能记 64 种不同的信息。 |
| `enc_blk_nums=[2,2,4,8]` | 2, 2, 4, 8 | **编码器**有 4 层，每层分别放 2、2、4、8 个处理块（工位）。越往深处工位越多，因为越抽象的信息越难处理。 |
| `dec_blk_nums=[2,2,2,2]` | 2, 2, 2, 2 | **解码器**有 4 层，每层各放 2 个处理块。 |
| `middle_blk_num=12` | 12 | **中间思考区**一口气放 12 个处理块，在最浓缩的图上反复琢磨。 |
| 预训练权重（warm-start）`NAFNet-SIDD-width64.pth` | 存在则用 | 见 2.4 小节。这是拿别人的 SIDD 权重当"起点"再继续练（也叫暖启动 warm-start）；**文件存在就用，不存在就随机初始化**（从零开始瞎猜）。 |
| 损失函数 L1 | `l1_loss` | 训练时"老师打分的标准"：把预测图和标准答案 GT 每个像素的差值取**绝对值**再全部加起来，越接近 0 越好。见下面单独解释。 |
| 优化器 AdamW | `lr=1e-4` | 模型"怎么改自己"的教练。学习率 = 每次改动的**步子大小**，`1e-4 = 0.0001`，很小的步子（怕改过头）。 |
| 调度器 CosineAnnealingLR | `T_max=30` | 学习率随时间变化的策略，像余弦曲线一样**前大后小慢慢降**：前期大步探索、后期小步精调。一个周期（30 个 epoch）走完一整条下降曲线。 |
| AMP / fp16 混合精度 | 开启 | 用"半精度"（见词汇表）省显存、加速，对结果影响极小。 |
| `patch_size=256` | 256 | 训练时从大图里**切小块**来学，一次只看 256×256 像素的一小块（patch），相当于一节课只精讲一页书。 |
| `batch_size=2` | 2 | 一次**同时**看 2 块 patch（一次"一口"吃 2 页书）。 |
| `stage1_epochs=30` | 30 | 把整个训练集从头到尾完整过 **30 遍**。每过一遍叫一个 epoch。 |
| `kind_2k_weight=0.7` | 0.7 | 每次取数据有 70% 概率走 **2K 档**（输入和答案都缩到 2K 大小），30% 走 **3.5K 档**。这样混着学，模型就"对分辨率不敏感"，将来任意分辨率都能用（这就是 4K 也能直接修的原因之一）。 |
| `num_workers=4` | 4 | 用 4 个"搬数据的小工"并行准备训练样本，加快取数据速度。 |
| `seed=42` | 42 | 给随机数定个"起点"，保证每次重跑结果可复现（同样的随机才出同样的实验）。 |
| `length_factor=2` | 2（训练时） | 训练时让每对图片每个 epoch 只出 2 个 patch，加快 epoch 迭代速度（数据集的默认 `length_factor=64` 才是正式使用的完整数量）。 |
| 保存路径 `ckpt_root: checkpoints` | `checkpoints/stage1_best.pth` | 训练完把模型参数（权重）存到这个文件，命名 `stage1_best.pth`（"最佳权重"的意思）。 |

下面把几个关键词单独展开讲清楚：

- **损失函数 L1**：想象老师在批改作业。模型交上来一张"修好的图"，老师拿出标准答案 GT，一格一格对——**每个像素都算"我改的和答案差多少"，取绝对值（只问差多少、不问谁大谁小），再把所有格子加起来**，得到一个数字叫"损失"（loss）。损失越小，说明改得越接近答案。L1 就是"绝对值求和"这种打分方式。我们每次训练只做一件事：**调整模型参数，让这个损失数字越来越小**。
- **学习率 lr=1e-4 与优化器 AdamW**：损失告诉我们"改得有多差"，但怎么改要靠"优化器"（optimizer，负责调整模型的教练）。教练每次迈多大的步子，就是**学习率**。`1e-4 = 0.0001`，步子很小——小步慢走不容易走错路，但也不会慢得离谱。AdamW 是优化器的一种牌子（一种成熟稳定的"迈步策略"，是 Adam 加了一点点防过拟合的改进）。就像走路时带上拐杖（动量，记得上次方向）又能自动控制步幅。
- **调度器 CosineAnnealingLR**：学习率如果永远一个值，前期太慢、后期又太冲。这个调度器让学习率**按余弦曲线的形状从大滑到小**：训练刚开始步子大一些，快速找到大致方向；越到后面步子越小，精雕细琢。一个周期正好对应 30 个 epoch，所以叫"余弦退火"。

**把训练循环串起来看（这样上面的零件就活了）**：一个 epoch 里，代码反复做这几件事——(1) 从数据流水线取出一小批 patch（batch_size=2）；(2) 把脏 patch 喂给 NAFNet 得到预测图；(3) 在 fp16 混合精度（autocast）下用 L1 损失算出"预测和标准答案差多少"；(4) 让优化器 AdamW 根据这个损失数字去调整模型参数；(5) 每走完一个 epoch，调度器把学习率往下调一档。这样滚 30 个 epoch，损失一路下降，模型越修越准。
- **AMP / fp16（混合精度）**：普通计算用 32 位小数（fp32），我们用一种"简化版"的 16 位小数（fp16）来算，内存占用少一半、速度快不少，而结果几乎看不出差别。这就像记账时先用草稿纸快速算（fp16），最后落账时才用正式账本（fp32）——又省纸又快。

### 2.4 "预训练 + 微调"到底在干嘛

- **预训练（pretraining）**：先用别人的、特别大的数据集把一个模型"从头到尾教一遍"，让它学会通用的能力——比如"照片大概长什么样、什么是噪点、怎么把噪点去掉"。这就像先**上完小学、中学、大学**，掌握了通用的基础本领。
- **微调（fine-tune）**：然后，在我们**自己的小数据集**（本项目是 78 对"脏照片—标准答案"的图片对）上继续训练，把通用的本领**调到我们这个任务的频道**上。这就像**入职后还要参加岗前培训**——大学知识是通用的，但具体到"我们这台相机拍出来的照片怎么修"，还得对着我们自己的例子再练一练。
- **本项目 Stage-1 的实际情况**：用 `NAFNet-SIDD-width64.pth` 这个**SIDD 预训练权重**当起点，在 ImagePairs 数据集上**微调 30 个 epoch**。这里的 **SIDD**（Smartphone Image Denoising Dataset，智能手机图像去噪数据集）是一个专门收录"手机拍照噪点照片 + 干净原图"的公开数据集。为什么拿它当起点？因为它跟我们的任务很像（都是"脏照片→干净照片"），模型已经有经验了，**站在巨人肩膀上**，学得又快又好。代码逻辑是：先检查 `vendor/NAFNet/weights/NAFNet-SIDD-width64.pth` 这个文件在不在——在就加载进来继续练（warm-start 暖启动）；不在就打印一句"未找到预训练权重，随机初始化"，从零开始瞎猜着学。加载时用了 `strict=False`，意思是"能对上的参数就对上，对不上的也不报错"——宽容一点，免得因为版本差异卡住。

### 2.5 车间一的"教材"是怎么准备的（数据流水线）

车间一要学习，就得喂它"题目 + 答案"。题目和答案是成对的：一张脏照片（LQ）+ 它对应的标准答案（GT）。数据怎么喂进模型，藏着不少细节，这里用大白话讲一遍：

- **图片怎么读进来**：用 OpenCV（一个常用的"读图"工具库）读两张图，把颜色顺序从 BGR 换成 RGB（不同库的默认顺序不一样），再除以 255 把数字归一化到 [0,1] 区间（0 纯黑、1 纯白），存成 32 位小数，方便后面做数学运算。配对规则是：除了以 `_gt.png` 结尾的文件，其余每张 `.png` 都去找它同名的 `_gt.png` 兄弟文件当标准答案。
- **两档分辨率怎么对齐（to_same_res）**：配对的题目和答案天生大小不一，训练前必须让它们一样大，否则没法逐像素对比打分。分两种档位：
  - **2K 档**：把大的标准答案**缩小**到跟题目一样大。
  - **3.5K 档**：把小的题目**放大**到跟标准答案一样大。
  缩放用的是双三次插值（INTER_CUBIC，一种根据周围像素"算出中间值"的质量不错的插值算法）。缩放完还要把数值**夹回 [0,1] 区间**——代码注释里特别说明，这是为了"消除 INTER_CUBIC 插值产生的振铃"：插值算法有时会在物体边缘画出一圈圈假光晕（ringing），夹一下能把它压住。
- **数据增强（augmentation）**：为了不让模型"挑角度"（照片横的竖的都要会修），训练时对题目和答案施加**完全相同的**随机变换：50% 概率水平翻转、50% 概率垂直翻转、随机旋转 90° 的倍数。关键原则是"题目和答案一起变"——就像打牌前先把两张牌粘在一起再洗牌，保证它们永远对齐。
- **切块（patch crop）**：模型一次看一整张大图太累、太费显存，所以训练时在题目和答案上**用同一个随机位置**各切一块 256×256（patch_size=256）。同一个位置保证"题目这一块 ↔ 答案这一块"严格对应，模型对的时候不会对错格子。
- **两级懒缓存（two-level lazy cache）**：解压大图很慢，代码为此建了两级缓存：第一级 `_decode_cache` 存"解码后的原始大图"，第二级 `_res_cache` 存"对齐好分辨率的结果"。某对图第一次被用到时才去算（这就是"懒"），算完存起来，后面直接用。78 对图片全部解码后大约占 **14 GiB** 内存，我们的机器有 125 GB 内存，完全放得下，换来的却是训练速度快很多。
- **每对图片出几道题**：数据集的默认设置下每对图片能产出较多 patch；但在训练脚本里特意把 `length_factor=2`，让**每对图片每个 epoch 只出 2 个 patch**——代码注释说这是为了"加速 epoch 迭代"（每轮过得更快，方便观察进度）。

这一整套流水线，本质上就是"给车间一准备教具"：把 78 对教材，切成成千上万块小例题，一块一块喂给它学。

## 3. Stage-2：SD2.1 潜空间扩散（车间二）

### 3.1 一句话介绍 + 比喻

> **扩散模型（diffusion model）** 的干活方式和我们想象的完全相反：它不是"从脏图擦干净"，而是"**从一团纯噪声里，一步步雕出一张清晰的图**"。

**比喻 1（捏雕塑）**：想象一大块灰色橡皮泥（纯噪声）。一位雕塑家不着急，先捏出大概的身体轮廓，再修脸，再刻眼睛、发丝，一步一步，越雕越细，最后雕出一尊精致的雕像。扩散模型每次"去噪一步"，就相当于雕塑家多雕一刀，20 刀下来，一尊"好照片"就成型了。

**比喻 2（显影照片）**：老式照片放进显影液里，图像不是瞬间出现，而是**从模糊的底片里一点一点"显"出来**，先有大轮廓，再出现细节。去噪的过程就像显影，每显一步图像清晰一点。

**关键点**：雕刀就是模型。模型训练时学会了"**什么样的图才像真照片**"，所以当它从噪声里一步步还原时，会自然地把"该有纹理的地方补上纹理，该平滑的地方抹平"——它能**无中生有地造出自然细节**。这正是扩散模型比普通"清洗式"修复网络（比如 Stage-1）**看起来更自然、更真实**的原因：一个在"擦"，一个在"创作"。

### 3.2 扩散模型的两步：正向加噪 / 反向去噪

- **正向过程（加噪，也叫 forward/diffusion）**：拿一张清晰图，一点一点往里面加随机噪声（可以理解成**一点一点打马赛克/撒雪花**）。加一次噪，图脏一点；加十次，基本认不出；加很多次之后，图彻底变成**一屏电视雪花（纯噪声）**。这一步在训练时用来"造题库"：我们告诉模型"从第几步的图变回清晰图"应该怎么做。
- **反向过程（去噪，也叫 reverse/denoising）**：训练一个网络，让它学会"**如何把噪声一步步去掉**"。给它一屏雪花，它倒着一步步还原：先还原成大轮廓，再还原出细节，最后变成清晰的图。它学的本质是"什么样的图才像真照片"——所以它能"猜"出画面里原本已经丢失的纹理，这就是它比普通网络"好看"的秘密。
- 我们把去噪的步数设为 **20 步**：每一步都向"干净"走近一点。步数越少越快但质量略降，越慢越精致但耗时间，20 是速度和质量的平衡点。

ASCII 示意（正着走：加噪；倒着走：去噪还原）：

```
   正向：一张清晰图，一步步加噪声，直到变成纯噪声
   ┌──────────────────────────────────────────────┐
   │  清晰图  →  加一点噪  →  加很多噪  →  …  →  纯噪声  │
   │   (GT)                                       (雪花屏) │
   └──────────────────────────────────────────────┘
                                 ↑ 训练时告诉模型："这步在变脏"
                                 │
                                 └───────────────┐
                                                 │ 反向：模型从纯噪声一步步去噪
   ┌──────────────────────────────────────────────┐
   │  纯噪声  →  去一步  →  再去一步  →  …  →  清晰图   │
   │   (雪花屏)                                   (修好的图) │
   └──────────────────────────────────────────────┘
```

你可能好奇：训练扩散模型需要什么教材？答案是**大量清晰的图片**——注意，并不需要脏图。因为正向加噪用清晰图就能制造出"从清晰到雪花"的无穷例题（每加一点噪就是一个新例题），反向去噪则让模型学着"倒着走回来"。模型由此学会了"雪花里可能藏着什么"——而"雪花里藏着的"，往往就是画面里原本已经丢失的细节。这就是它能"无中生有"补细节的根源。

> 注意：Stage-2 干活时其实不需要"从纯噪声开始"这么极端。我们可以把"还没那么脏"的图（比如车间一修好的图）作为起点，往它身上撒**一小把**噪声（这正是后面的 SDEdit，见 3.5），再让模型去噪回来。这样模型既有发挥空间（补细节），又不至于跑太远（跑远就没法保真了）。

### 3.3 "潜空间"是什么（压缩再干活，省力）

- **潜空间（latent space）**：直接对几千万个像素做去噪，又慢又费显存。聪明的办法是：先用一个叫 **VAE**（变分自编码器，Variational Auto-Encoder，一种"压缩—还原"工具）的网络，把大图**压缩成一张很小的"潜图"（latent）**——注意，这张小图里的数字**不再是颜色**，而是"抽象的浓缩信息"，所以人眼看不懂它，但它忠实记录了原图的精华。扩散模型就在这张小图上干活（去噪），因为图小，**快得多、省显存得多**。干完活，再用 VAE 的解码器把潜图**放大还原**回正常的彩色大图。
- **比喻**：写长文章很费劲，那就**先把文章浓缩成一段提纲，在提纲上修改，改好了再扩写回全文**。潜图就是"提纲"，扩散就是在"改提纲"，VAE 解码器负责"扩写回文章"。又省力，结果又稳（因为改动发生在紧凑的提纲上，不容易乱）。

用 ASCII 图看这条"压缩 → 干活 → 还原"的路径：

```
   大图（几千万个数字）                      大图（还原回来的彩色图）
        │                                        ▲
        ▼                                        │
   [VAE 编码器]  ────▶   □□□□  ◀────  [VAE 解码器]
     （写提纲）         潜空间            （扩写回全文）
                       （改提纲的地方，
                        扩散在这里干 20 步活）
```

- 好处总结：**省显存、算得快、更稳**。这也是"潜空间扩散"这个名字的由来。

### 3.4 SD2.1 是谁，本项目怎么用它（DiffBIR v2.1 集成）

- **SD2.1（Stable Diffusion 2.1）**：一个开源、现成的"文生图"扩散模型，社区里的明星。它可以靠一句话描述画出一张图。我们**不**用它来"按文字作画"，而是**借用它的"去噪网络（UNet）"来当精修工人**——我们不给它文字，而是给它"参照图"，让它照着参照图来修。这套借用的思路叫"图像修复版的扩散"。这里先认识一下 **UNet**（念作"U 网"）：它是一种**中间收窄、两边对称、形状像字母 U** 的网络结构——和我们在第 2 节讲 NAFNet 时的那个"漏斗"是同一个家族（都先缩后放）。扩散模型的去噪网络就是一个 UNet，靠它来"一手一脚地雕刻"。
- **DiffBIR v2.1**：一个把扩散模型改装成"**图像修复工具**"的开源框架。它帮我们做了很多工程上的脏活（加载权重、管理去噪流程、分块处理大图等）。我们直接复用它（代码在 `vendor/DiffBIR/` 里），并传入一套我们自己的参数。
- **ControlNet（一个"遥控器/夹子"）**：扩散模型天性爱自由发挥，得有个东西把它"夹住"，让它照着输入图来。**ControlNet** 就是这样一个"夹子"——它接收一张"控制图"（这里是车间一输出的干净图），生成一个"控制信号"，把去噪过程**朝着控制图的方向拽**。本项目用的 ControlNet 叫 **IRControlNet**（IR = Image Restoration，图像修复），它的底子是 SD2.1 的 UNet 结构。控制图就是一张普通的彩色像素图（电脑里用一个四维数组装着：第三维是红绿蓝三张，开头还有一个"批次"维度，细节不用纠结），在 `apply_cldm` 里被 VAE 编码成潜空间的"控制信号"再送进网络。
- **`apply_cleaner` 替换为恒等（identity）**：DiffBIR 原本在正式去噪前，会先用一个"cleaner"（清理器，通常是个小修复网络）自己预处理一遍输入图。我们把这一步**替换成一个"原样放行"的空操作**（代码里 `_pipeline.apply_cleaner = lambda lq, tiled, tile_size, tile_stride: lq`，直接返回原输入）。为什么要换？因为我们的车间一（NAFNet）已经清过一次了，我们就想让车间一的输出**原封不动**地成为车间二的"参照图"，不让 DiffBIR 再插一脚。这就是两个车间真正"接上线"的地方。
- **`task="sr"`、`upscale=1`**：`sr` 是"超分辨率（Super Resolution）"任务模式，DiffBIR 在这个模式下会走"修复 + 放大"的流程。但我们把 `upscale=1`（放大倍数为 1 倍，即**不放大**）——因为我们做的是**同分辨率精修**，不是把图变大。于是 DiffBIR 的"超分上采样器"就被关掉了，只剩下"修复/精修"能力为我们所用。
- **两份大权重 + 一个小坑**：Stage-2 靠两份预训练权重干活，都放在 `vendor/DiffBIR/weights/` 下：`sd2.1-base-zsnr-laionaes5.ckpt`（约 5.16 GB，可以理解成画师的"基本功底"）和 `DiffBIR_v2.1.pt`（约 1.45 GB，DiffBIR 的"图像修复专用技能包"）。工程上有个小坑：加载权重时代码会**按当前工作目录**去找 `weights/` 文件夹，所以程序会先 `chdir`（切换目录）到 `vendor/DiffBIR/` 再构建模型。以后如果看到"找不到权重"的报错，十有八九是没切对目录。
- 其他传入的重要参数（都来自 `_make_args` 和 `run`）：`device='cuda'`（用显卡算）、`captioner='none'`（不用文字描述器，因为我们是图像驱动不是文字驱动）、`precision='fp16'`（半精度省显存）、`guidance=False`（关掉额外的文本引导）、`seed=231`（随机种子，保证可复现）、`strength=1.0` + `start_point_type='noise'`（这两个合在一起的意思是：**去噪起点就是纯噪声**，从噪声完整走满 20 步去噪。注意：这跟后面 3.5 的预留旋钮 `n`（SDEdit，先撒一小把噪声再还原）**不是一回事**——`strength=1.0` 是当前实际生效的值，`n` 目前只是预留）。

### 3.5 采样与关键参数（大白话讲一遍）

"去噪要一步步走"，这 20 步怎么安排、每步跨多大，就是**采样器（sampler）**管的事。我们用的采样器叫 **`edm_dpm++_3m_sde`**（一个专为扩散模型设计的、稳定又质量好的采样算法；`3m` 表示它内部用一个三阶近似，`sde` 表示它在连续时间域上走）。你不需要记住这个名字，只要知道：**它负责把"20 步去噪"安排得又快又好**。

| 参数 | 我们用的值 | 大白话解释 |
|---|---|---|
| 采样器 sampler | `edm_dpm++_3m_sde` | 去噪"怎么迈步"的算法，质量与速度兼顾。 |
| 步数 steps | 20 | 从噪声雕到清晰图一共走 20 刀。少则快但糙，多则慢但细，20 是平衡点。 |
| CFG 强度 cfg_scale | `w = 2.0` | **CFG（Classifier-Free Guidance，无分类器引导）** 是"让模型多听话"的旋钮：越大越死板地贴着参照图（保真），越小越放飞自我（让先验自由发挥）。2.0 是安全的中间值（取值范围 1~3）。 |
| 去噪强度 / SDEdit | `n = 0.15`（预留） | **SDEdit**（Stochastic Differential Editing，随机微分编辑）思想：动手雕之前先往参照图上撒一点噪声再还原。撒得越多（n 越大），改得越狠、越"重造"；撒得越少（n 越小），越贴着原图、越保真。0.15 = "小撒一把、轻修"。**注意**：在目前代码里 `n` 这个旋钮只是预留的（设计文档说它是"预留给后续任务的噪声与提示权重"），`engine.py` 和 `stage2.py` 里还没真正使用它。 |
| 精度 precision + autocast | fp16 + `torch.autocast('cuda', torch.float16)` | **全程用半精度计算**。这不是可选项：如果不用，4K 大图会**卡死/显存爆掉（OOM）**。这是工程上真实踩过的坑，代码里特意用 `torch.autocast` 把整个 `pipeline.run()` 包起来。 |
| 噪声增强 noise_aug | 0 | 不额外加噪声增强（关掉）。 |
| 顺序 order / eta | order=3, eta=0 | 采样器内部的"精度档位"和随机性控制，取稳妥值，不用纠结。 |

**关于 4K 的坑（值得知道）**：直接把 DiffBIR 的函数在进程内调用时，如果不包 `torch.autocast`，它就会按 fp32（全精度）跑，而 VAE 的分块中间结果被缓存在 CPU 上，内存翻倍，4K 图（4096×3072）会**卡死或耗尽内存**。加了 fp16 自动混合精度之后，4K 图（20 步）大约 **7~8 分钟一张**，与命令行版本相当。我们还靠 **DiffBIR 内部的自动分块（tiling）** 来省显存（这是它自己干的，不用我们手动切）：ControlNet 的参照图按 **512×512 一块、步距 384**（即相邻块重叠 128）来喂；VAE 编码/解码按 **256×256 一块**。分块就像把一块大地板分成小瓷砖来铺——每次只搬一小块，内存压力小很多。

### 3.6 现在 stage-2 为什么不微调 + 将来怎么改

- **现状**：Stage-2 目前是**直接使用现成的 SD2.1 / DiffBIR v2.1 预训练权重**，**没有**针对我们的图片对做任何训练。它用的两份大权重（都存在 `vendor/DiffBIR/weights/` 下）：一个是 SD2.1 的基础模型 `sd2.1-base-zsnr-laionaes5.ckpt`（约 5.16 GB，可以理解为画师的"基本功底"），另一个是 `DiffBIR_v2.1.pt`（约 1.45 GB，可以理解为"图像修复专用技能包"）。因为画师没专门练过"我们这台相机拍糊的照片"该怎么修，它对**我们的退化类型（模糊、噪声的"脾气"）**不够了解——这正是最终视觉效果还不那么理想的原因之一。
- **将来方向**：用我们配对的真实数据给 UNet 做 **LoRA 微调**。**LoRA**（Low-Rank Adaptation，低秩适配）是一种"**只小改模型一小部分参数**"的轻量训练法——不重训整个大模型（太贵），而是往关键位置加几个小小的"调节旋钮"，只转这几个旋钮就达到针对性训练的效果。计划是：rank（秩，可理解为调节旋钮的"档位数"）取 16~32，patch（裁剪块）取 256~512，用"真实退化 → 干净图"的配对数据，让画师学会"我们这组相机拍糊 → 该怎么修"。这样它就不再是"通用画师"，而是"认识我们相机脾气的老朋友"。**这是写进设计文档的改进方向，但当前还没有实现**——文档里明确标注为"未来工作"。

设计文档里还写明了将来的具体做法：把 512×512 的裁剪块**编码进潜空间**，用"条件潜码 + GT 潜码"共同监督训练；同时刻意把适配器做得**很小**——因为手上只有 78 对数据，模型太大会"过拟合"（把教材背得滚瓜烂熟，但一遇新题就傻眼）。用小适配器 + 把混合旋钮 λ 调小，是防备过拟合的两件法宝。

## 4. 两个车间怎么协作（一张图走完整条流水线）

完整数据流（ASCII 图，从左到右看）：

```
   一张 LQ 脏照片进来
        │
        ▼
   ┌───────────────────────┐
   │  Stage-1  NAFNet      │   车间一：洗净、捋直（保真打底）
   │  （基础清理）           │
   └───────────────────────┘
        │
        ▼
   初步干净图  ───────────────────┐
        │                          │（把车间一的输出当作"参照图"）
        ▼                          ▼
   ┌───────────────────────┐  ┌───────────────────────┐
   │  Stage-2  SD2.1 扩散   │←│  ControlNet（夹子）      │
   │  （精修：补细节纹理）     │  │  照着参照图来修           │
   └───────────────────────┘  └───────────────────────┘
        │
        ▼
   精修图（自然、有细节）
        │
        ▼
   ┌───────────────────────┐
   │  融合旋钮（见下）        │   λ 混合 + α 高频回注
   └───────────────────────┘
        │
        ▼
   最终输出（又干净又自然）
```

**为什么把车间一的输出（而不是原图）送给车间二？** 因为车间一已经先把噪点、模糊清理了一遍，车间二**不需要从头对付脏东西**，只需专注于"补细节、让纹理自然"。这就像画师拿到手的是"已经擦干净、打好草稿的画布"，而不是一张脏兮兮的纸——画师只需精修，不用浪费时间清污。而且车间一修过的图更稳定，喂给扩散模型，它"自由发挥"的空间被约束得更合理，保真度更高。

**融合公式（用大白话 + 公式双轨讲）**：车间一输出叫 `stage1`，车间二输出叫 `diffused`，原始输入叫 `input`。最后一步把它们合起来，有两个旋钮：

**① 混合（lambda 混合，旋钮 λ）**：

```
out = (1 - λ) × stage1  +  λ × diffused
```

大白话：`λ` 决定"最终结果听谁的"。λ=0 就是 100% 听车间一的（只做基础清理）；λ=1 就是 100% 听车间二的（完全由画师做主）；我们配置文件里 λ = **0.2**，也就是**20% 听精修、80% 听基础清理**——偏向保真。设计文档里还给了安全默认值建议 λ≈0.3，最终以配置文件为准（这些旋钮未来会按比赛官方指标重新校准）。

举个例子更直观：假设某个像素，车间一（stage1）输出 0.7，车间二（diffused）输出 0.9，λ=0.2，那么混合后 = 0.8 × 0.7 + 0.2 × 0.9 = 0.56 + 0.18 = **0.74**。看，结果更靠近车间一的 0.7——因为车间一占了大头。

**② 高频回注（旋钮 α）**：

```
out = out + α × (input − 原图的模糊版)
```

大白话：把原图拿来，用模糊滤镜（高斯模糊，sigmaX=3.0）涂一遍得到"模糊版"，**原图减掉模糊版**就只剩下"细小的边缘和高频细节"（相当于原图里最精细的那层信息）。再把这些精细细节**按 α 的比例补回**结果里。为什么补？因为扩散和混合会多少"抹平"一些边缘，把原图本来有的锐利细节补一点回来，可以**低成本恢复 4K 纹理、还提升 PSNR 分数**。我们配置文件里 α = **0.5**（设计文档安全默认 α≈0.4）。最后所有数值夹回 [0,1] 区间（防止颜色越界）。

**每个旋钮一句话记忆法**：

| 旋钮 | 管什么 | 一句话记忆 |
|---|---|---|
| **λ** | 混合比例 | λ 管**保真/感知**：偏 0 信车间一（保真），偏 1 信车间二（感知）。 |
| **n** | 撒噪声多少 | n 管**改多狠**：小 = 轻修保真，大 = 重造感知（当前代码中预留、未使用）。 |
| **w** | CFG 听话程度 | w 管**多听话**：高 = 死贴条件（保真），低 = 放飞先验（感知）。 |
| **α** | 高频细节回补 | α 管**细节回补**：把原图锐利边缘补回来，提纹理、提 PSNR。 |

> 顺带一提：在一次参数验证（Task 11 的验证网格）里，用 lam=0.2 / n=0.15 / w=2.0 / alpha=0.5 这组配置跑过，得到 PSNR 24.505 / SSIM 0.739 / NIQE 4.201。**PSNR**（峰值信噪比）和 **SSIM**（结构相似度）是"跟标准答案比有多像"的参考指标（越高越好），**NIQE** 是"看起来多自然"的无参考指标（越低越好）。这些分数不用背，知道它们是打分的尺子即可。注意：题目里提到的"最终值 0.2/0.15/2.0/0.5"其实是**当前配置文件里实际用的值**；而设计文档里写的安全默认值是 λ≈0.3、n≈0.15、w≈2、α≈0.4——两者并存，以配置文件为准，等比赛官方权重公布后还要再校准。

**4K 大图怎么不爆内存（整图为主 + 分块兜底）**：真正上工时，照片可能是 4096×3072 的 4K 大图。我们的主路径是：**把整张图交给 DiffBIR，让它内部自己分块处理**（ControlNet 参照图 512×512、步距 384，VAE 编码/解码 256×256）。**万一整图路径出错**，我们还有一条备用的"**自己逐块过一遍再拼**"的兜底路径（`_stage2_tiled`）：把大图切成一块块小瓷砖，分别过模型，再把结果拼回去。拼回去不是硬拼，而是用**线性互补权重**做"边界平滑过渡"：每一块在边缘处权重从 1 线性降到 0（代码里就是 `np.linspace(0→1)` 和 `np.linspace(1→0)`），相邻块重叠的区域按权重加权求和——这样拼缝处就不会出现明显的接缝线。特别要注意：**拼接发生在像素域**（直接的图片像素上），而不是在潜空间里拼——在潜空间拼块容易破坏扩散的连贯性。实测 4K 图（20 步）约 **7~8 分钟一张**，峰值内存约 40 GB（其中大部分是 CUDA 统一内存——一种让显卡内存和普通内存自动互通、显存不够时可以借用普通内存的机制，所以实际 GPU 显存占用小于 20 GB）——这个数字说明：开 fp16 + DiffBIR 内部自动分块之后，4K 在我们的机器上是跑得动的。

## 5. 术语速查表（词汇表）

下面这张表按**拼音字母序**排列，每个词配一句大白话。想复习的时候回来翻它就行。

| 术语 | 大白话一句话 |
|---|---|
| **AdamW** | 一种"优化器"牌子，负责调整模型参数；AdamW 是 Adam 加了一点防过拟合的改进，稳当好用。 |
| **AMP（Automatic Mixed Precision）** | "自动混合精度"：计算时多数用 16 位小数（快、省显存），关键处用 32 位，两全其美。 |
| **batch（批次）** | 一次同时处理的样本数量。batch_size=2 就是一次看 2 块图。 |
| **CFG（Classifier-Free Guidance，无分类器引导）** | "让模型多听话"的旋钮；值越大越贴着参照图，越小越自由发挥。 |
| **ControlNet** | 给扩散模型配的"夹子/遥控器"，接收一张控制图，把去噪过程朝着这张图的方向拽。 |
| **DiffBIR** | 一个把扩散模型改装成"图像修复工具"的开源框架，我们复用它来跑 Stage-2。 |
| **diffusion（扩散）** | 从一团纯噪声里一步步"雕"出清晰图的生成方式；训练时则是把清晰图一步步加噪。 |
| **Decoder（解码器）** | "扩写/还原"部分：把压缩的小图（或潜图）放大还原回完整图。 |
| **Encoder（编码器）** | "压榨/提炼"部分：把大图逐层缩小，提取越来越抽象的信息。 |
| **epoch（轮）** | 整个训练集从头到尾完整过一遍叫一轮。30 轮 = 过 30 遍。 |
| **fp16** | 16 位半精度小数，比 32 位省一半内存，速度更快，结果几乎无差别。 |
| **GT（Ground Truth）** | 标准答案：这张图"原本应该长什么样"，用来给模型打分。 |
| **latent（潜空间/潜码）** | 把大图压缩成的"浓缩版小图"，人眼看不懂，但记录精华；扩散在这里干活。 |
| **L1（损失）** | 打分方式：预测和答案每个像素差的绝对值加起来，越小越好。 |
| **学习率（learning rate）** | 模型每次改动的"步子大小"。lr=1e-4 就是每次只挪 0.0001 步。 |
| **LoRA（Low-Rank Adaptation，低秩适配）** | 只小改模型一小部分参数的轻量训练法，像只转几个小旋钮，省钱又高效。 |
| **LQ（Low Quality）** | 低质量图：输入的脏照片（模糊、有噪点）。 |
| **NAFNet** | 我们的车间一：一个"图进图出"的图像修复网络，负责基础清理。 |
| **patch（裁剪块）** | 从大图上切出的小方块，训练时一次看一块。patch_size=256 就是 256×256 像素一块。 |
| **pixel（像素）** | 图片最小的小方块，每个像素由 R/G/B 三个数字描述颜色。 |
| **SDEdit（Stochastic Differential Editing）** | "先撒一点噪声再还原"的轻修法：撒得越少越保真，越多越重造（对应旋钮 n）。 |
| **SIDD（Smartphone Image Denoising Dataset）** | 智能手机拍照去噪数据集，NAFNet 预训练权重的来源。 |
| **Stable Diffusion（SD）** | 开源"文生图"扩散模型；SD2.1 是我们借用的"去噪工人"。 |
| **upscale（放大）** | 把图变大的倍数。upscale=1 就是 1 倍、不放大，只精修。 |
| **UNet（U 网）** | 一种中间收窄、两边对称、形状像字母 U 的网络结构（和 NAFNet 的漏斗同族）；SD2.1 用它当"去噪雕刻手"。 |
| **VAE（变分自编码器）** | 压缩—还原工具：编码器把大图压成潜图，解码器把潜图还原成大图。 |
| **权重（weights）** | 模型"记忆"存放的地方，即所有参数。加载权重 = 把之前学的东西装回来。 |
| **通道（channel）** | 一层同时记几种信息的"小本子"数量。width=64 = 64 个小本子。 |
| **采样器（sampler）** | 安排"去噪 20 步怎么走"的算法。我们用的是 edm_dpm++_3m_sde。 |
| **卷积（convolution）** | 神经网络最基础的"扫描取特征"动作：一个小方窗在图上滑过，逐格提取局部信息，像用放大镜一格一格观察并做笔记。 |
| **分辨率（resolution）** | 图的长宽像素数。4K ≈ 横向约 4000 像素。 |
| **损失函数（loss function）** | "老师打分的标准"：量化模型结果和答案差多少，越小越好。 |
| **微调（fine-tune）** | 在预训练基础上，用我们的小数据继续练，把通用能力调到我们的任务频道。 |
| **推理（inference）** | 训练完之后"上工"：拿新照片喂给模型，让它直接输出结果，不再学习。 |
| **预训练（pretraining）** | 先用别人的大数据集从头教一遍，学到通用能力（先上完小学中学）。 |

## 6. 一句话总结

> 我们的照片修复系统，是一座**有两间车间的小工厂**：**车间一 NAFNet** 像一台老实的**自动洗护机**，先把脏照片**洗净捋直**（保真打底）；**车间二 SD2.1 扩散** 像一位懂行的**画师**，从一团噪声里**一步步雕出自然细节**（感知补足）；最后通过 **λ 混合、n 撒噪、w 听话、α 回补** 四个小旋钮把两位师傅的作品按比例融合——**又像原图，又自然好看**，这就是我们的"两阶段同分辨率图像增强系统"。
